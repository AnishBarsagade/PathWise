1. Executive Summary

PathWise is a full-stack web application designed to optimize last-mile delivery logistics for the city of Nagpur. The system combines four algorithmic components — A* pathfinding, Analytic Hierarchy Process (AHP), a multi-factor cost function, and Google OR-Tools' Capacitated Vehicle Routing Problem (CVRP) solver — to generate cost-optimized delivery routes for a mixed fleet of vehicles.

This report documents the complete analysis of the existing PathWise codebase and presents 15 proposed features and enhancements organized by implementation priority. Each proposal includes a description, technical rationale, affected components, and estimated effort. A phased implementation roadmap is provided for a structured 8-week development cycle.

📌 Key Finding
The project has a strong algorithmic foundation and well-structured backend, but lacks data visualizations, real-time interactivity, and rider-facing workflow completion — areas that would significantly elevate the project for academic evaluation and demonstration.

2. Current System Overview

PathWise provides a complete logistics dispatch workflow:

  1. Data Entry: Admin creates delivery orders and registers fleet vehicles in the database.
  2. Optimization: The system runs a multi-factor VRP optimization considering 6 weighted factors.
  3. Visualization: Optimized routes are displayed on an interactive Leaflet map with stop sequences.
  4. Rerouting: Dynamic scenario-based rerouting handles real-world incidents (road closures, traffic, weather, accidents).
  5. History: All optimization runs and rerouting events are persisted in SQLite for audit and comparison.

  • Seeded Admin Account — Default admin@pathwise.com is created on first run
  • Leaflet Map Integration — Interactive maps with delivery markers and route lines

5. System Architecture & Data Flow

The system follows a three-tier architecture with Python subprocess integration for algorithmic computation:

ComponentTechnologyResponsibility
Presentation LayerReact + Vite + TailwindUser interface, maps, form validation, route visualization
Application LayerExpress.js + Node.jsREST API, authentication, business logic, data validation
Algorithm LayerPython + OR-ToolsAHP weight calculation, cost function, VRP optimization
Data LayerSQLite (WAL mode)Persistent storage for users, deliveries, vehicles, runs, events
External ServicesOpen-Meteo + OSRMLive weather data, road geometry for map routes

Communication pattern: Frontend → Express REST API → Python subprocess (stdin/stdout JSON) → SQLite persistence → Express response → Frontend render.

9. Proposed Features — 🔴 High Priority

These features deliver the highest academic value and visual impact for project evaluation.

High Priority

Feature 1: Interactive Analytics Dashboard with Charts

Add rich data visualizations using a charting library (Recharts or Chart.js):

  • Bar chart — Deliveries by zone distribution
  • Pie chart — Vehicle utilization breakdown by class
  • Line chart — Total cost trend across optimization runs over time
  • Donut chart — Priority distribution (High / Medium / Low)
  • Horizontal bar — Per-vehicle load vs. capacity comparison

Technical rationale: Currently the Dashboard and Results pages display only raw numeric values. Charts transform data into instantly comprehensible visual narratives, which is critical for college project presentations and reports.

📁 Affected: Dashboard.jsx, Results.jsx ⏱️ Effort: 3–4 days 📦 New dependency: recharts
High Priority

Feature 2: Time Window Constraints (VRPTW Upgrade)

Upgrade the optimization engine from CVRP (Capacitated VRP) to CVRPTW (VRP with Time Windows):

  • Add earliest_time and latest_time fields to the deliveries table and UI form
  • Add a "Time" dimension to the OR-Tools routing model with AddDimension()
  • Apply CumulVar constraints for each delivery node's time window
  • Update the cost function to incorporate time-based penalties

Technical rationale: Time windows are a fundamental real-world logistics constraint. This upgrade demonstrates deep understanding of combinatorial optimization and is a significant algorithmic differentiator for academic projects.

📁 Affected: vrp_solver.py, deliveries schema, RouteOptimizer.jsx ⏱️ Effort: 5–7 days
High Priority

Feature 3: Integrate A* into the VRP Pipeline

Replace the Haversine straight-line distance calculation with actual road-network shortest paths using the A* algorithm:

  • Build a road graph for Nagpur from OSRM or OpenStreetMap data
  • Use the existing A* implementation with a proper haversine heuristic
  • Generate A*-based distance and travel time matrices as input to the VRP solver
  • Cache computed paths for repeated node pairs

Technical rationale: The README flow diagram shows A* as a step in the pipeline, but it currently runs as a standalone demo only. Integrating it makes the project's documented architecture actually accurate.

📁 Affected: astar.py, vrp_solver.py ⏱️ Effort: 4–5 days
High Priority

Feature 4: Rider Mobile View with Delivery Status Updates

Create a dedicated rider-facing interface for delivery execution:

  • Mobile-optimized route view showing assigned deliveries on a map
  • Status buttons: ✅ Completed · ❌ Failed · 🔄 Attempted
  • New API endpoint: PATCH /api/deliveries/:id/status
  • Automatic progress tracking with percentage completion bar
  • One-click reroute trigger from the rider's own vehicle

Technical rationale: Closes the delivery workflow loop. Currently riders have no way to update delivery status, making the system incomplete as an end-to-end logistics solution.

📁 New: RiderDashboard.jsx, new API endpoints ⏱️ Effort: 4–5 days
High Priority

Feature 5: Live Traffic Data Integration

Replace the hardcoded traffic score (3.0) with real traffic data:

  • Integrate TomTom Traffic Flow API (free tier: 2,500 requests/day) or HERE Routing API
  • Fetch traffic congestion levels between delivery coordinate pairs
  • Map API response to the existing 1–5 traffic score scale
  • Display live traffic conditions on the map overlay

Technical rationale: The AHP cost function assigns 17.06% weight to "Traffic", but it's currently a static constant. Real traffic data makes this factor dynamic and meaningful.

📁 Affected: realtimeService.js, vrp_solver.py ⏱️ Effort: 3–4 days

14. Conclusion

PathWise is a well-architected delivery route optimization system with a solid algorithmic foundation combining AHP multi-criteria decision making, multi-factor cost evaluation, and Google OR-Tools CVRP optimization. The project demonstrates competence in full-stack development, mathematical modeling, and logistics engineering.

The 15 proposed enhancements in this report address the key gaps in data visualization, real-time interactivity, rider workflow completion, and algorithmic depth. Implementing even a subset of the high-priority features (particularly the analytics dashboard, rider status view, and VRPTW upgrade) would significantly elevate the project from a functional prototype to a comprehensive, presentation-ready logistics platform.

The phased roadmap provides a structured path for incremental improvement, ensuring each development sprint delivers demonstrable value while maintaining system stability.
